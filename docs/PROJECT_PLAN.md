# Project plan

## Working principle

Each milestone ends in a small commit that is runnable, tested, and honest about
what is still missing. Results are generated by code and committed as artifacts;
they are never typed into the report independently.

## Milestones and intended commit sequence

| Phase | Intended commit | Exit criterion |
|---|---|---|
| 0 | `chore: establish evaluation-first project foundation` | Scope, risks, gates, and decisions are written before modelling |
| 1 | `feat(data): reconstruct leakage-safe Tesco conversations` | Deterministic thread builder, sample fixture, and reconstruction tests |
| 2 | `analysis: profile Tesco traffic and historical outcomes` | Reproducible brand audit, date distribution, thread quality, and failure examples |
| 3 | `feat(labels): define intent and routing annotation codebook` | Mutually usable labels, ambiguity rules, and pilot agreement results |
| 4 | `feat(eval-data): freeze the 200-example golden set` | IDs frozen, hashes recorded, no overlap, second-annotation slice present |
| 5 | `feat(baselines): add trivial and rule-plus-BM25 baselines` | Same input/output schema and evaluation path as the main system |
| 6 | `feat(retrieval): index outcome-aware historical precedents` | Blinded pooled relevance sample, Precision@3/nDCG@3, self-case exclusion tests |
| 7 | `feat(agent): add grounded drafting and policy-gated escalation` | Structured output, evidence validation, deterministic safety tests |
| 8 | `feat(eval): add selective-risk and reply-quality evaluation` | Confidence intervals, risk–coverage, pairwise tables, raw predictions |
| 9 | `eval: validate LLM judge against blinded human ratings` | Agreement, position swap, repeatability, and decoy results |
| 10 | `docs: publish results, failures, caveats, and decision log` | Maximum six-page report or equivalent concise README section |
| 11 | `chore: verify clean-room reproduction under 15 minutes` | Fresh environment succeeds from documented command; final tag created |

Commit names may change to describe the actual diff; phases and exit criteria
will not be silently weakened.

The phase-6 metric was corrected before relevance labels were collected:
Recall@3 is not identifiable from a judged top-k pool because relevant documents
missed by both systems remain unknown. The replacement reports explicitly pooled
Precision@3 and nDCG@3 plus paired query wins/ties/losses; this is a validity fix,
not a post-result relaxation.

## Non-negotiable acceptance gates

- Golden set has 150–250 genuinely human-reviewed examples.
- No golden conversation or target case is available to training or retrieval.
- Thresholds are selected on development data, never on the final golden labels.
- At least 50 examples have independent second-human labels.
- Every reported aggregate is reproducible from committed per-example outputs.
- Routing reports both unsafe automation and needless escalation.
- Reply evaluation contains deterministic safety checks and human ratings.
- LLM-judge agreement is reported per dimension with disagreement examples.
- At least two baselines run through the same harness.
- Final headline reproduction completes offline in less than 15 minutes.
- The report contains five real failure modes and the mandatory misleading-number
  section.

## Experimental discipline

1. Record dataset hashes, code commit, random seeds, model identifiers, prompts,
   and pricing assumptions in each run manifest.
2. Keep immutable per-example predictions for every compared system.
3. Use bootstrap intervals for sampled metrics and binomial confidence bounds for
   safety-event rates.
4. Report the natural slice and challenge slice separately.
5. Preserve negative results and failed hypotheses in the decision log.
6. Add tests for every discovered leakage path or unsafe behavior.

## Likely review questions

- What evidence makes a historical conversation a successful resolution?
- Can related turns or customer-specific templates cross the evaluation boundary?
- What does model confidence mean, and is it calibrated?
- What happens when retrieval is fluent but irrelevant?
- How does the policy trade automation value against unsafe mistakes?
- Would the judge accept a polite hallucination or invented promise?
- Which claims are valid only for a short, public, 2017 Twitter snapshot?

The implementation and report must answer each question with an artifact, test,
or labelled example.
