# Data card

## Source

- **Dataset:** Customer Support on Twitter
- **Publisher:** Thought Vector and collaborators
- **Primary page:** <https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter>
- **Shape:** 2,811,774 rows and seven columns in `twcs.csv`

The raw dataset is not committed to this repository. Users rebuilding derived
artifacts must obtain it from the primary publisher and comply with the license
shown on the Kaggle dataset page.

The intent families are supported by a deterministic, training-only lexical
coverage and example audit in [the taxonomy derivation note](TAXONOMY_DERIVATION.md).
It is descriptive evidence for the chosen boundaries, not a labelled dataset.

## Relevant fields

| Field | Use |
|---|---|
| `tweet_id` | Stable anonymized message key |
| `author_id` | Brand handle or anonymized customer identifier |
| `inbound` | Direction relative to the support brand |
| `created_at` | Ordering and chronological splitting |
| `text` | Customer or brand message |
| `response_tweet_id` | Zero, one, or multiple child message IDs |
| `in_response_to_tweet_id` | Parent message ID |

Conversation structure is a directed graph, not a guaranteed alternating list.
Comma-separated response IDs create branches, and numbered brand replies may be
split across several tweets.

## Initial audit observations

These figures are exploratory and will be regenerated by a checked-in audit
command before they are used in the report:

- 2,809,474 rows are dated 2017.
- 2,790,961 rows (approximately 99.3%) are dated October–December 2017.
- Tesco authored 38,573 outbound rows.

The dates include a small number of older referenced messages, so the global
minimum date does not describe the primary collection window.

## What the data does not prove

- A brand reply does not prove that the customer's problem was resolved.
- Movement to a private message hides the consequential part of many cases.
- A positive final message can thank an agent while the underlying issue remains.
- A missing follow-up is not evidence of success.
- A 2017 link, product fact, refund rule, or escalation path is not necessarily
  current policy.
- Text may refer to an image that is unavailable to the model.

Accordingly, the current reranker uses explicitly weak, non-ground-truth tiers
such as `positive_followup_proxy`, `unresolved_followup_proxy`,
`private_handoff_without_outcome`, and `no_customer_followup`. Retrieval
relevance is evaluated separately by a blinded human; none of these proxy tiers
is presented as verified resolution.

## Leakage risks

1. Splitting individual rows can put adjacent turns on opposite sides.
2. Retrieving the target response or another turn from its conversation trivially
   inflates grounding quality.
3. Repeated customers and nearly identical numbered reply fragments can leak
   templates.
4. Building the taxonomy or thresholds after inspecting final gold labels turns
   the evaluation set into development data.

Splits are therefore conversation-level and chronological. Artifact creation
uses only the training partition, and both creation and reproduction reject any
retrieved target case or target-conversation evidence.

## Privacy and ethics

Customer author IDs are anonymized in the dataset. This project will preserve
that anonymization, redact sensitive-looking sequences in released samples, and
make no attempt to recover identities. Examples in the report will be limited to
what is necessary for analysis and attributed to the dataset.
